# 结构化推荐设计

2.1.0 将推荐从固定文案与固定分数升级为图谱、论文和课题上下文共同驱动的候选生成与透明排序。该阶段不引入大模型结论，也不把关键词检索包装成完整系统综述。

## 候选与评分

每条推荐保留来源节点、支撑论文、实验变量、停止条件、成本、风险和检索范围。已知领域模板只提供实验设计知识，最终候选是否存在取决于当前图谱。实时检索没有方法节点时，系统优先生成证据矩阵任务，而不是虚构新的材料关系。

排序由课题相关性、实验可行性、证据完整度和新颖性组成，权重依次为 0.40、0.25、0.20 和 0.15。相关性来自当前目标、阶段、进展、目标与约束中的明确关键词；可行性同时考虑证据属性和实验限制；证据完整度考虑直接关联论文数量、实时元数据与近期证据；新颖性只表示候选的迁移和验证状态。总分用于候选之间的相对比较，不是实验成功概率。

## 反证与检索边界

“核查潜在反证与边界”使用当前方向的查询词追加 limitations、challenges 和 stability，实时请求 OpenAlex。返回论文只作为待阅读线索，界面不会自动把它们标为已证实反证。只有阅读题目、摘要和原文后，研究者才能判断它是否构成反例、限制条件或适用边界。

每个检索记录保存查询词、返回数量与核查时间。未执行方向检索时，推荐明确显示当前只使用精选示例。执行后也只声明本次 OpenAlex 元数据检索范围，不把“未发现”写成真实研究空白。

## 渐进披露

2.1.0 同时展开全部依据后，用户反馈推荐有用但信息过多。2.1.1 因此将默认内容限制为验证假设、最小实验和支撑论文，把评分、推荐理由、变量、风险、检索范围与反证核查收进“推荐依据与边界”。右侧推荐卡采用相同的按需展开方式。用户已确认调整后的信息量合适。

## 验证

`tests/recommendations.test.ts` 检查候选来源、评分字段、支撑文献、停止条件、检索范围和课题变化对分数的影响。`src/lib/export.ts` 将评分拆解、变量、风险、停止条件和检索范围一并写入 Markdown 简报，避免界面中的关键边界在导出后丢失。
