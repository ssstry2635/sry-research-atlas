# 论文检索的稳定性设计

4.5.0 不再让浏览器直接依赖 OpenAlex 的匿名共享额度。搜索先经过插件 Host 的同源 `/bohr-api/search` 接口，由 Host 统一处理来源、失败回退和缓存。

## 来源顺序

Host 首先请求 OpenAlex，使用题目、作者、年份、引用、摘要索引和开放获取元数据。若 OpenAlex 返回 403、429、超时、空结果或其他错误，Host 自动切换到 Crossref 的期刊论文检索。Crossref 请求固定 `type:journal-article`，排除补充材料条目，并读取 DOI、题目、作者、年份、期刊、摘要、被引次数和 DOI 链接。两条来源都失败时，才会尝试使用未过期的同查询缓存；没有缓存才向界面返回中文错误。

界面以每篇论文的 `source` 标明 `OpenAlex` 或 `Crossref`。搜索提示也显示实际使用的来源，不把回退隐藏成“OpenAlex 成功”。Crossref 的摘要覆盖率低于 OpenAlex，缺少摘要时悬浮卡会明确显示，并让 DSH 模型按“摘要信息不足”处理。

## 缓存与额度

Host 对规范化后的查询词保留 15 分钟内存缓存，相同查询会直接返回 `Crossref cache` 或 `OpenAlex cache`，避免重复消耗免费额度。缓存只存在当前 Host 进程，不写入论文知识库。

若要获得更稳定的 OpenAlex 独立额度，可以在启动 DSH 的 Host 环境设置 `OPENALEX_API_KEY`。Host 只在环境变量存在时附加该参数，不会把密钥写入浏览器、插件清单或知识库。没有 API key 时，默认的 Crossref 回退仍然可用。

## 中英概要的保底链路

检索结果进入发散网络后，Host 会批量生成英文概括、中文对照和关键发现。4.5.2 不再把一批 JSON 的成败当成整批成败：批量输出被截断或漏项时，缺失论文逐篇重试；模型逐篇仍失败时，用题目和可用摘要生成保守的英文概括，并调用 DSH 翻译服务生成中文；最后仍不可用时返回明确的中文题录级说明并标注“仅有题录信息”。每篇结果都会返回非空中文概要，不会因为一条解析失败就让整组论文显示翻译失败。

实测 Crossref 的 5 篇结果全部成功返回中文：其中 1 篇有摘要，生成了包含方法与 PCE 数值的中文概要；4 篇无摘要，均明确说明只有题录信息，只翻译并谨慎概括题目，没有补写实验结论。

## 独立网页降级

独立网页没有 Host 接口时，客户端依次尝试直连 OpenAlex 和 Crossref。浏览器会直接显示 Crossref 来源，并在全部来源失败时显示包含具体 HTTP 状态的中文错误。Host 插件环境优先使用服务端缓存与来源切换，不经过这条降级链。

## 验证

`GET /bohr-api/search?q=CsPbBr3%20perovskite%20nanocrystals` 在当前环境返回 200、`source: "Crossref"` 和 8 篇结果；紧接着的相同请求返回 `source: "Crossref cache"`、`cached: true`。这确认了 OpenAlex 限流时的回退和缓存行为。知识库工具和模型摘要链路不受检索来源切换影响。

用户已在实际 DSH 页面确认：4.5.2 不再出现 OpenAlex 429，实时论文均能显示中文概要，点击单篇论文后同页其他论文保持显示。
